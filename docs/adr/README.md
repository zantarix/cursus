# Architecture Decision Records

| ADR | Title | Status | Summary |
|-----|-------|--------|---------|
| [ADR-000](000-founding-constraints.md) | Founding Constraints and Initial Choices | Accepted | Retrospective capture of day-zero constraints: static binary distribution as a hard requirement, Rust chosen to enable that goal, CLI as the user-facing interface, dual CLI/library artifact, JavaScript and Cargo as founding package managers, Nix flakes for development, and Claude Code for AI-assisted development. |
| [ADR-001](001-project-initialisation.md) | Project Initialisation | Accepted | `cursus init` creates `.cursus/config.toml` via TUI wizard with package manager detection for both interactive and non-interactive contexts. |
| [ADR-002](002-changeset-recording.md) | Changeset Recording | Accepted | `cursus change` records per-package semver bump level and description as TOML-frontmatter Markdown files in `.cursus/`, with conflict-free multi-branch support. |
| [ADR-003](003-release-command.md) | Release Command | Accepted | `cursus release` consumes changesets to bump versions, generate changelogs, and delete consumed changeset files -- filesystem only, no git operations. |
| [ADR-004](004-publish-command.md) | Publish Command | Accepted | `cursus publish` publishes all configured packages to their respective registries, with idempotent handling of "already published" errors. |
| [ADR-005](005-github-releases.md) | GitHub Releases Integration | Accepted | Opt-in GitHub Releases creation during `publish`, with changelog-derived release notes, artifact uploads, and `GITHUB_TOKEN` authentication. |
| [ADR-006](006-git-lifecycle-hooks.md) | Git Lifecycle Hooks | Accepted | Opt-in `[git]` config section for automated commit, tag, and push operations after `release`, with `--no-git` escape hatch. |
| [ADR-007](007-honor-private-packages-during-publish.md) | Honor Private Package Markers During Publish | Accepted | Skip packages marked `private: true` (npm) or `publish = false` (Cargo) during `cursus publish` instead of failing. |
| [ADR-008](008-dry-run-local-only-guarantee.md) | Dry-Run Must Be Strictly Local-Only | Accepted | `--dry-run` guarantees zero side effects: no filesystem writes, no network requests, no subprocess mutations -- Cursus owns this guarantee, never delegates to external tools. |
| [ADR-009](009-javascript-package-manager-strategy.md) | JavaScript Package Manager Strategy | Accepted | Detect lockfile type for `npm install`-based lock updates with configurable `lock_command` override; always use `npm publish` for registry publishing. |
| [ADR-010](010-scoped-release-changeset-consumption.md) | Scoped Release Changeset Consumption | Accepted | When `--package` scopes a release, rewrite multi-package changesets to remove only the released packages instead of deleting the entire file. |
| [ADR-011](011-command-execution-strategy.md) | Command Execution Strategy | Accepted | All user-configurable commands execute via `/bin/sh -c` with standardized dry-run, error handling, and working directory conventions. |
| [ADR-012](012-workspace-protocol-dependency-updates.md) | Skip workspace: Protocol Dependencies | Accepted | Skip `workspace:` protocol entries during intra-workspace version propagation with a warning, since these are resolved at publish time by the package manager. |
| [ADR-013](013-logging-infrastructure.md) | Logging Infrastructure | Accepted (backend superseded by [ADR-018](018-replace-fern-with-cli-logger.md)) | Adopt the `log` crate facade for all application output, migrating from raw `println!`/`eprintln!`; route Info/Debug/Trace to stdout, Warn/Error to stderr. |
| [ADR-014](014-verbose-mode.md) | Verbose and Silent Modes | Accepted | Stackable `-v` and mutually exclusive `-s` global flags controlling log level: `-s` = Error, default = Info, `-v` = Debug, `-vv` = Trace. |
| [ADR-015](015-ci-managed-release-workflow.md) | CI-Managed Release Workflow | Accepted | `cursus ci` smart entrypoint that infers prepare vs publish from repo state; `strategy` field (`push`/`branch`) replaces `run_until`; tags always created during `publish`. |
| [ADR-016](016-rename-release-to-prepare.md) | Rename `release` to `prepare` | Accepted | Rename the `release` subcommand to `prepare` to accurately reflect that it prepares release artifacts without publishing anything. |
| [ADR-017](017-late-guard-dry-run-pattern.md) | Late Guard Pattern for Dry-Run | Accepted | Run all logic unconditionally and guard only final mutations at the lowest abstraction boundary via `DryRunCommandRunner` decorator and `dry_run` parameters. |
| [ADR-018](018-replace-fern-with-cli-logger.md) | Replace fern with CliLogger | Accepted | Replace unmaintained `fern` crate with a ~30-line hand-rolled `CliLogger` implementing `log::Log` directly, with zero new dependencies. |
| [ADR-019](019-improved-init-workflow.md) | Improved Init Workflow | Accepted | Expand `cursus init` into an 8-screen interactive-only TUI wizard covering package managers, manifest paths, git automation, and GitHub integration with progressive disclosure. |
| [ADR-020](020-tui-screen-submodule-structure.md) | TUI Screen Submodule Structure | Accepted | Structure each TUI wizard as a submodule directory with one file per screen, keeping shared types and dispatchers in `mod.rs`. |
| [ADR-021](021-commit-references-in-changelog-entries.md) | Add Commit References to Changelog Entries | Accepted | Attach commit SHA and optional PR number to each changelog entry at `prepare` time using `git log --first-parent --diff-filter=A`; render as forge-autolinkable `[abc1234] via #123` suffix. |
| [ADR-022](022-distribution-strategy.md) | Distribution Strategy for Cursus Binaries | Proposed | Distribute via GitHub Releases (primary, static binaries for all targets) and npm `@zantarix/cursus` (secondary, postinstall downloads platform binary from GitHub release). No bundled binaries in npm; hard failure on download error; no Node.js wrapper. |
| [ADR-023](023-dependency-propagation-bumps.md) | Dependency Propagation Bumps During Prepare | Proposed | Automatic version bumps for packages that depend on bumped packages. Configurable `dependency_bump` (`auto`/`match`/`patch`/`minor`/`major`, default `auto`). Two-phase mark-then-sweep handles cyclic dependencies. Linked packages exempt from propagation. Scoped prepare generates changesets for out-of-scope dependents. |
| [ADR-024](024-linked-package-versions.md) | Linked Package Versions in Monorepos | Proposed | Optional `[linked-versions]` config to keep package versions in sync: global linking (all packages) or user-defined groups with glob patterns. Max-version-wins algorithm ensures convergence and monotonicity. Scoped prepare errors on partial linked-group overlap. Validation runs during `prepare`/`ci` only. |
| [ADR-025](025-auto-changeset-from-conventional-commit.md) | Add `--auto` Flag to Derive Changesets from Conventional Commits | Accepted | `cursus change --auto` reads the single Conventional Commit on the current branch, derives a changeset (fix→patch, feat→minor, BREAKING→major) scoped to changed projects, and optionally commits+pushes when `git.enabled = true` (suppressible via `--no-git`). Any valid commit type accepted; multi-commit branches exit as no-ops for recursion prevention. |
| [ADR-026](026-per-package-change-level-in-tui.md) | Per-Package Change Level Selection in TUI Wizard | Accepted | Redesign `change` TUI into a V-shaped two-step flow: a combined package-selection-and-per-package-level screen (or a simplified single-package screen for single-package repos), followed by an inline message editor with Ctrl+E escape to external editor. Wrapping level controls, bulk `,`/`.` adjustment, group toggles (`a`/`c`/`u`), mouse support, and Alt+Enter/Shift+Enter for newlines. |
