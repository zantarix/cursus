- **ADR-012** (Accepted): Skip workspace: Protocol Dependencies During Intra-Workspace Version Propagation — skip and warn on `workspace:` protocol entries in npm dependency version propagation during release.
- **ADR-013** (Accepted, backend superseded by ADR-018): Adopt the log Crate with fern for Application Logging — `log` facade + `fern` backend with split-stream routing (Info/Debug/Trace to stdout, Warn/Error to stderr). - **ADR-014** (Accepted): Add Verbose and Silent Modes via Global CLI Flags — stackable `-v` flag and mutually exclusive `-s` flag on `GlobalArgs` controlling log level filter (`-s` = Error, default = Info, `-v` = Debug, `-vv` = Trace). Depends on ADR-013.
- **ADR-015** (Accepted): CI-Managed Release Workflow — `cursus ci` smart entrypoint infers prepare vs publish from repo state. Tags always created during `publish` after registry publishing (never during `release`/`prepare`). `strategy` field replaces `run_until`: `push` | `branch` (no `commit` or `tag` variants). Default derived: `branch` when `[github].enabled`, `push` otherwise. `branch` strategy: checkout release branch, commit there, push, optionally create PR, checkout back (no `git reset`). Pre-flight check: refuses to run with uncommitted changes. `release_branch_prefix` config + `--branch` CLI override. Auto-creates PR when `[github].enabled`. `--no-git` extended to `publish`. Errata moved to affected ADRs (003-006, 008).
- **ADR-016** (Accepted): Rename `release` Subcommand to `prepare` — the `release` subcommand is misleading because it does not release anything; `prepare` accurately describes its function (version bumps, changelogs, commits, branch management). Config fields and commit messages using "release" as a noun are retained. `cursus ci` dispatches to `prepare`/`publish` internally.
- **ADR-017** (Accepted): Adopt Late Guard Pattern for Dry-Run Implementation — run all logic unconditionally, guard only the final mutation at the lowest abstraction boundary. `DryRunCommandRunner` decorator handles subprocess mutations; `dry_run: bool` parameter on `write_version`/`update_dependency_version`/`Changelog::update` handles direct filesystem writes; `GitHubClient` calls remain gated at orchestration level. `--dry-run` promoted to `GlobalArgs`. Eliminates prediction methods like `lock_file_path()` and prevents drift between dry-run and real code paths.
- **ADR-018** (Accepted): Replace fern with Hand-Rolled log::Log Implementation — `fern` flagged as unmaintained by Renovate; replaced with ~30-line `CliLogger` struct implementing `log::Log` directly in `src/main.rs`. Zero new dependencies. Preserves identical formatting, stream routing, and level filtering. Supersedes the backend sub-decision from ADR-013; `log` facade unchanged.
- **ADR-019** (Accepted): Improve Init Workflow — expand `cursus init` into interactive-only TUI wizard covering git automation, GitHub integration, multi-package-manager selection, and manifest path prompting. TUI grows from 2 to 8 screens with progressive disclosure. Package manager screen changes from single-select to multi-select. ManifestPath and EditGitHub screens use `ratatui-textarea` for text input. Branch strategy implies GitHub (skips EnableGitHub screen). Generated config includes commented-out documentation for all options. OpenEditor screen offers to open config in `$VISUAL`/`$EDITOR`. All non-interactive CLI flags removed (including `--package-manager`); scripts write TOML directly. ConfirmOverwrite screen replaces old Confirm screen (only shown when config exists).
- **ADR-020** (Accepted): Structure TUI Wizards as Submodule Directories with One File per Screen — each wizard becomes a directory (`src/tui/<wizard>/`) with `mod.rs` holding shared types, dispatchers, entry point, test helpers, and cross-screen workflow tests, plus one file per screen containing its handler, renderer, and tests. Screen functions use `pub(super)` visibility to avoid `private_interfaces` lint. Submodule tests access parent items via `super::super::` paths.
- **ADR-021** (Accepted): Add Commit References to Changelog Entries — at `prepare` time, resolve the introducing commit for each changeset file via `git log --first-parent --diff-filter=A`, extract optional PR number from commit message, and append `[abc1234] via #123` suffix to changelog bullets. Forge-autolink format, no URL construction, no `[github].enabled` dependency. Graceful degradation: `debug!` when git disabled, `warn!` when git enabled but lookup fails.
- **ADR-022** (Proposed): Distribution Strategy for Cursus Binaries — two channels: GitHub Releases (primary, static binaries for all 7 targets attached to each release) and npm `@zantarix/cursus` (secondary, postinstall script downloads platform binary from GitHub release). No bundled binaries in npm; hard failure on download error; no Node.js wrapper; direct native binary as npm bin entry. Publish order: Cargo -> npm -> GitHub release. All targets handled uniformly including riscv64 and aarch64-windows.
- **ADR-023** (Accepted): Dependency Propagation Bumps During Prepare — automatic version bumps for packages that depend on bumped packages during `prepare`. Configurable bump level via `[prepare].dependency_bump` (default `"auto"`): `auto` (patch unless upstream was major), `match` (mirrors upstream level), or fixed `patch`/`minor`/`major`. Two-phase mark-then-sweep algorithm handles cyclic dependency graphs. Linked packages (ADR-024) are exempt from propagation bumps. Scoped `--package` prepare generates changesets for out-of-scope dependents. Changelog entries under "Dependencies" category.
- **ADR-024** (Accepted): Linked Package Versions in Monorepos — optional `[linked-versions]` config section for lockstep versioning. Two modes: global (`enabled = true`, all packages linked) and group-based (`[[linked-versions.groups]]` with glob patterns). Max-then-bump algorithm: find highest current version across the group, find highest change type across group changesets, bump the max current by that change type (or converge to max current if no changesets). Self-healing convergence for desynced versions. Packages bumped by linking receive changelog entries; one entry per package across all internal mechanisms (linking + dependency propagation). Scoped `--package` prepare: rejected outright with global linking; errors on partial linked-group overlap with group-based linking (must include all or none). Validation runs during `prepare` and `ci` only, not `change`. Errata: reconciliation now runs as two passes (before and after dependency propagation per ADR-023) to maintain linked-version invariant when propagation raises a group member.
- **ADR-025** (Accepted): Add `--auto` Flag to Derive Changesets from Conventional Commits — `cursus change --auto` reads the single commit on the current branch (compared against `origin/HEAD`), parses it as a Conventional Commit, and derives a changeset (fix→patch, feat→minor, BREAKING CHANGE→major). Syntactically invalid messages error; any valid type without semver significance exits successfully with no changeset (no fixed allowlist). Changeset scoped to projects with changed files in the commit; no changeset written if no files match known projects. `--no-git` flag suppresses git commit/push even when `git.enabled = true` (for Renovate after-update hooks). When `git.enabled = true` and `--no-git` not passed, commits and pushes the changeset immediately. Multi-commit branches exit as no-ops (zero exit code) for recursion prevention. Mutually exclusive with `--change-type`, `--message`, and interactive mode. Dry-run supported per ADR-008/ADR-017.

- **ADR-027** (Accepted): Adopt Mutation Testing as a Test Quality Verification Strategy -- best-effort manual `cargo mutants` runs to verify test quality beyond coverage. Two strategies for missed mutants: add a test (genuine gaps) or simplify code (equivalent mutations). `#[mutants::skip]` reserved for untestable entry points only. Not in CI. — redesign `change` TUI into a V-shaped two-step flow. First step: combined package-selection-and-per-package-level screen (multi-package) or dedicated single-package screen (single-package repos). Both converge on second step: inline multi-line message editor (Enter submits, Alt+Enter/Shift+Enter for newlines, Ctrl+E terminates TUI and drops to external editor). Change levels wrap cyclically (patch→major→minor→patch for Right/forward). Bulk `,`/`.` keys shift first checked package then force all others to match. Group toggle keys (`a`/`c`/`u`) and mouse click support on project rows. Default level is patch. `ChangeResult` updated to carry per-package levels and completion mode (inline vs editor). Non-interactive path unchanged.
- **ADR-028** (Accepted): Support npm OIDC Trusted Publishing — detect OIDC-capable CI environments (GitHub Actions via `ACTIONS_ID_TOKEN_REQUEST_URL`, GitLab CI via `CI_JOB_JWT_V2`) and `NODE_AUTH_TOKEN` presence as boolean flags on `Env`. Three pre-publish warnings: `NODE_AUTH_TOKEN` overriding OIDC, no authentication configured, missing `publishConfig.provenance` for public packages. `ProjectInfo` extended with `publishconfig_provenance` field during npm enumeration. No new config fields or provenance flag on `NpmConfig`. Applies to all JS package managers since publishing always uses `npm publish` (ADR-009). First publish of new packages still requires classic token (npm limitation).
- **ADR-029** (Accepted): Warn on Missing Cargo Registry Token Before Publish — emit `warn!()` before `cargo publish` when `CARGO_REGISTRY_TOKEN` is not detected (tracked as boolean flag on `Env`). Does not inspect `~/.cargo/credentials.toml`. Warning only, never blocks.
- **ADR-030** (Accepted): Separate Binary and Library Crates with Environment Injection — retrospective capture. The library never reads the ambient environment directly. The binary constructs `Env` (carrying `CommandRunner`, editor, `GitHubClient`) from real env vars and CWD, passes it to `run_with()`. Filesystem access always uses caller-provided paths. `GitWorkdir` assembled inside the library from injected primitives. Enables full test isolation via `RecordingCommandRunner` and temp directories.
- **ADR-031** (Accepted): Guard Publish and CI Against Never-Prepared Packages Using CHANGELOG.md — secondary safeguard using `CHANGELOG.md` presence for edge cases where the normal changeset-based flow is bypassed (developer forgot to file changeset, or scoped prepare consumed it). `ci` excludes packages without it from tag-missing checks (preventing false publish dispatch). `publish` warns and skips them without adding to the `blocked` set, preserving publishability of their dependents. Primary defence is the changeset flow itself: pending changesets cause `ci` to dispatch to `prepare`, not `publish`.
- **ADR-032** (Accepted): Verify Changeset Presence on Feature Branches — `cursus verify` checks whether the current branch has added at least one `.cursus/*.md` file using `git diff --name-only --diff-filter=A <base>..HEAD`. `--base` flag (default `origin/HEAD`). Three exit codes: 0 (changeset found), 1 (error), 2 (no changeset). Always non-interactive. Read-only (no config loading, no filesystem writes). Not integrated into `ci` — standalone CI helper for pre-merge checks. No built-in escape hatch; CI policy left to pipeline configuration. Dry-run is a no-op (command is already side-effect-free).
